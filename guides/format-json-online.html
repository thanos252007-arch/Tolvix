How to Format JSON Online: A Beginner-Friendly Guide

Make JSON easier to read, check whether its syntax is valid, and learn how to spot common formatting mistakes.

← Back to Tolvix tools

JSON (JavaScript Object Notation) is a text format used to store and exchange structured data. APIs, configuration files and many applications use it because it represents information with familiar objects, arrays, strings, numbers, booleans and null values.

JSON can be valid even when it is written on one long line. Formatting—also called pretty-printing—adds indentation and line breaks so people can inspect the structure more easily. Formatting does not make incorrect JSON valid by itself; the syntax must first pass parsing.

Example: before and after formatting

A compact JSON object can be difficult to scan:

{"name":"Asha","active":true,"skills":["SQL","Python"],"city":"Pune"}

The same data is easier to inspect when indented:

{
  "name": "Asha",
  "active": true,
  "skills": [
    "SQL",
    "Python"
  ],
  "city": "Pune"
}

Both examples represent the same JSON values. Whitespace outside strings is insignificant to JSON parsing, so indentation changes readability rather than the underlying data.

Formatting vs. minifying vs. validating

  • Formatting: adds indentation and line breaks to make nested data readable.
  • Minifying: removes unnecessary whitespace to make the JSON text more compact. It does not encrypt or protect the data.
  • Validating: checks whether the text follows JSON syntax. A formatter can only safely format input that parses successfully.

Common JSON errors and how to fix them

Missing or extra commas

Object properties and array items are separated by commas. A missing comma between properties causes a parse error. A trailing comma after the final item is not permitted in standard JSON.

Using single quotes

JSON strings and property names must use double quotes. For example, {"city":"Pune"} is valid, while {'city':'Pune'} is not valid JSON.

Unquoted property names

Property names must be double-quoted strings. Write {"score":95}, not {score:95}.

Invalid values

JSON supports strings, numbers, objects, arrays, true, false and null. Values such as undefined, NaN and comments are not part of standard JSON syntax.

Practical tips before sharing JSON

  • Check that the top-level value is the object or array expected by the receiving API.
  • Keep property names and data types consistent with the API documentation.
  • Do not mistake minification for encryption; never share passwords, access tokens or confidential records unnecessarily.
  • After editing, validate the final text again rather than assuming it remains valid.

Read a JSON structure before changing it

Start by identifying the outermost value. An object begins and ends with braces, while an array uses square brackets. Inside an object, each property has a quoted name, a colon and a value. Arrays contain ordered values and may contain objects of their own. Understanding this nesting makes it easier to find the exact comma, bracket or quote that caused a parser error.

Debug a large response safely

  • Copy the original response before editing it.
  • Use the error position, if shown, to inspect the nearby character; the actual mistake can be just before that position.
  • Check opening and closing braces and brackets in pairs.
  • Look for unescaped quotation marks or backslashes inside strings.
  • After making a correction, validate the complete JSON again.

When working with API responses, compare the property names and value types with the API documentation. A syntactically valid document can still have the wrong schema for the application that consumes it.

Frequently asked questions

Does formatting change the JSON data?

Proper formatting changes whitespace outside strings, not the represented values. It should preserve the data structure.

Can a formatter repair every invalid JSON file?

No. A formatter can identify syntax errors, but it cannot safely guess what missing values, commas or property names you intended. Correct the reported issue and validate again.

Is JSON the same as a JavaScript object?

No. JSON is a text data format with stricter syntax. JavaScript object literals may allow features—such as unquoted keys or trailing commas—that standard JSON does not.

Can I minify JSON to make it secure?

No. Minifying only removes unnecessary whitespace. It does not encrypt, anonymise or access-control the content.
